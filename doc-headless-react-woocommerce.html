Migration headless React + WooCommerce

Objectif : garder WordPress comme back-office, construire l'affichage public en React/Vite, gérer le panier en React, puis laisser WooCommerce gérer le paiement.

React

  • Accueil
  • Produits

  • Panier

WooCommerce

  • Paiement natif
  • Commandes
  • Moyens de paiement
  • Emails transactionnels

Architecture

Le front React doit reprendre les pages publiques importantes. WordPress reste disponible pour l'administration, les médias, les produits WooCommerce et les endpoints REST. 

React
├── Accueil
├── Produits
├── Fiches
└── Panier

WooCommerce
└── Paiement
Règle principale : React affiche et prépare le panier. Dès que l'utilisateur clique sur payer, il est redirigé vers la page checkout WooCommerce native.

Routes SEO à conserver

Structure actuelle des permaliens WordPress : /%postname%/

URL Responsable Usage
/ React Accueil
/boutique/ React Liste des produits
/produit/:slug/ React Fiche produit WooCommerce
/collections/:slug/ React Catégorie produit
/panier/ ou /cart/ React Panier headless
/commande/ ou /checkout/ WooCommerce Paiement natif
Le site contient des pages françaises et anglaises pour le panier/checkout. Il faut choisir une URL canonique avant la mise en production pour éviter les doublons SEO.

Endpoints API

Base locale actuelle : http://localhost/MAGICIEUSE/htdocs/wp-json

Besoin Endpoint
Pages WordPress GET /wp/v2/pages
Page par slug GET /wp/v2/pages?slug=la-magicieuse
Produits GET /wc/store/products
Produit par slug GET /wc/store/products?slug=slug-produit
Catégories produits GET /wc/store/products/categories
Panier GET /wc/store/cart

Panier React

Le panier React doit utiliser la Store API WooCommerce. Les appels doivent conserver les cookies de session. 

fetch('/wp-json/wc/store/cart', {
  credentials: 'include'
})

Actions nécessaires

  • Lire le panier courant.
  • Ajouter un produit depuis une fiche React.
  • Modifier les quantités.
  • Supprimer une ligne.
  • Afficher sous-total, total et taxes si présentes.
  • Rediriger vers le checkout WooCommerce.

Endpoints panier

  • GET /wc/store/cart
  • POST /wc/store/cart/add-item
  • POST /wc/store/cart/update-item
  • POST /wc/store/cart/remove-item

Paiement WooCommerce

Le paiement reste côté WooCommerce pour éviter de réimplémenter les moyens de paiement, la validation commande, les emails et les règles de livraison.

Depuis React, le bouton de paiement du panier doit pointer vers l'URL checkout retenue : /commande/ si on conserve l'URL française, ou /checkout/ si on garde la configuration actuelle.

Étapes à faire

  1. Choisir les URLs canoniques : /panier/ ou /cart/, /commande/ ou /checkout/.
  2. Créer le projet React/Vite.
  3. Configurer React Router avec les mêmes URLs SEO.
  4. Créer un client API WordPress/WooCommerce.
  5. Construire la page Accueil.
  6. Construire la liste Produits.
  7. Construire la fiche produit via le slug.
  8. Construire le panier React avec la Store API.
  9. Tester le passage panier React vers checkout WooCommerce.
  10. Configurer les règles serveur pour servir React sur les routes publiques et laisser WordPress gérer /wp-admin, /wp-json et les uploads.
  11. Mettre en place les redirections 301 pour les anciennes URLs non retenues.

Points d'attention

Technique

  • WooCommerce est ancien et génère des warnings avec PHP 8.3.
  • La Store API doit être testée tôt sur ajout, quantité et suppression.
  • Les variations produit peuvent demander un traitement spécifique.
  • Les contenus Elementor ne sont pas toujours propres via REST.

SEO

  • Garder les slugs produits existants.
  • Éviter les doublons entre pages françaises et anglaises.
  • Conserver les URLs médias WordPress.
  • Prévoir titres, descriptions et données structurées côté React.
